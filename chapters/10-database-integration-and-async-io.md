## Give each request its own database session

A database engine manages connectivity and a connection pool. A session groups database work into a unit of interaction and tracks pending changes. Create the engine once for the application, then open and close a session for each request that needs one.

Do not share one mutable `Session` across requests or concurrent tasks. A session is stateful and represents one unit of work.

This chapter uses SQLAlchemy 2.0 with SQLite for examples. Install SQLAlchemy in the project environment:

~~~sh
python -m pip install "sqlalchemy>=2,<3"
~~~

## Define a mapped database model

SQLAlchemy 2.0 uses typed declarations with `Mapped` and `mapped_column`:

~~~python
from sqlalchemy import String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class Book(Base):
    __tablename__ = "books"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(160), index=True)
    author: Mapped[str] = mapped_column(String(120))
~~~

The table name and column definitions describe the database structure. Keep a database model separate from request and response models so each layer can change for its own reason.

## Configure a local SQLite engine and session factory

The engine is shared by the application. `sessionmaker` creates new session objects bound to it:

~~~python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

DATABASE_URL = "sqlite:///./notes.db"

engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False},
)
SessionLocal = sessionmaker(
    bind=engine,
    autoflush=False,
    autocommit=False,
)
~~~

SQLite uses `check_same_thread=False` because FastAPI may handle parts of one request from different worker threads. This setting does not make a session safe to share between requests.

For another database, use the matching SQLAlchemy driver and connection URL. Keep credentials in environment-based configuration rather than committing them to source control.

## Provide a session with a `yield` dependency

Use a dependency to close the session even if an endpoint raises an exception:

~~~python
from collections.abc import Generator

from sqlalchemy.orm import Session


def get_db() -> Generator[Session, None, None]:
    with SessionLocal() as session:
        yield session
~~~

The `with` block closes the session when dependency cleanup runs. Each incoming request gets its own session instance.

## Create a table for a local exercise

For a small local experiment, create the table from the model metadata:

~~~python
Base.metadata.create_all(bind=engine)
~~~

This is convenient while learning, but it does not replace schema migrations. Existing databases need a controlled way to add, rename, and remove columns without losing data. Use a migration tool such as Alembic for application schema changes.

## Create and read records from FastAPI

Use a request model for input and a response model for public output. The session is injected as a dependency:

~~~python
from typing import Annotated

from fastapi import Depends, FastAPI, status
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy import select
from sqlalchemy.orm import Session

app = FastAPI()


class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=160)
    author: str = Field(min_length=1, max_length=120)


class BookPublic(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    author: str


Database = Annotated[Session, Depends(get_db)]


@app.post("/books", response_model=BookPublic, status_code=status.HTTP_201_CREATED)
def create_book(payload: BookCreate, db: Database):
    book = Book(title=payload.title, author=payload.author)
    db.add(book)
    db.commit()
    db.refresh(book)
    return book


@app.get("/books", response_model=list[BookPublic])
def list_books(db: Database):
    return db.scalars(select(Book).order_by(Book.id)).all()
~~~

These endpoints are regular `def` functions. FastAPI runs regular path operations in a worker thread, which is appropriate for blocking synchronous database calls. Do not run blocking database calls directly inside an `async def` route.

`commit()` writes the transaction. `refresh()` loads values generated by the database, such as the new primary key. A list operation uses `select()` and returns the matching records.

## Roll back a failed transaction

A failed commit leaves the session transaction unusable until it is rolled back. Catch a known database error, roll back, and translate it into a safe HTTP error:

~~~python
from fastapi import HTTPException
from sqlalchemy.exc import IntegrityError


def insert_unique_record(db: Session, record: Book):
    db.add(record)
    try:
        db.commit()
    except IntegrityError as exc:
        db.rollback()
        raise HTTPException(
            status_code=409,
            detail="A record with these values already exists",
        ) from exc
    db.refresh(record)
    return record
~~~

Catch only database errors the application can handle. Do not return the database error text to a client because it can expose table names, constraints, or data.

## Choose sync or async database I/O

`async def` does not make a synchronous database driver non-blocking. Choose a synchronous session with a regular `def` route, or choose an async driver and `AsyncSession` with awaited database operations.

For a local async SQLite exercise, install the async driver:

~~~sh
python -m pip install aiosqlite
~~~

Create an async engine and a session factory:

~~~python
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

async_engine = create_async_engine(
    "sqlite+aiosqlite:///./async-notes.db",
    echo=False,
)
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,
    expire_on_commit=False,
)
~~~

To create the mapped tables with an async connection in a local exercise, run the synchronous metadata operation through `run_sync`:

~~~python
async with async_engine.begin() as connection:
    await connection.run_sync(Base.metadata.create_all)
~~~

Production schema changes should still use migrations.

An async dependency yields a new session for the request:

~~~python
from collections.abc import AsyncGenerator

from sqlalchemy.ext.asyncio import AsyncSession


async def get_async_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        yield session
~~~

Use `await` for operations that perform database I/O:

~~~python
from typing import Annotated

from fastapi import Depends
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

AsyncDatabase = Annotated[AsyncSession, Depends(get_async_db)]


@app.get("/async-books", response_model=list[BookPublic])
async def list_books_async(db: AsyncDatabase):
    result = await db.scalars(select(Book).order_by(Book.id))
    return result.all()
~~~

Do not run one `AsyncSession` concurrently in multiple tasks. Give each concurrent task its own session. Async database access helps when the driver and every I/O operation in the route are actually asynchronous; it does not make CPU-heavy work faster.

## Close the async engine at application shutdown

An async engine owns pooled connections. Dispose of it when the application shuts down. FastAPI lifespan can manage that boundary:

~~~python
from contextlib import asynccontextmanager

from fastapi import FastAPI


@asynccontextmanager
async def lifespan(app: FastAPI):
    yield
    await async_engine.dispose()


app = FastAPI(lifespan=lifespan)
~~~

Keep the engine and session factories in a module that application setup can import. The next chapters cover configuration and lifespan patterns in more depth.

1. Define a SQLAlchemy model and create a local SQLite database.
2. Add a `yield` dependency that creates one session for each request.
3. Create a record with `add`, `commit`, and `refresh`, then read records with `select`.
